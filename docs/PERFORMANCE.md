# 0.4.1 飞行性能与飞机设计

设计不再以“能连接零件”为通过标准。模型输出必须同时通过结构、合同先决条件和确定性性能筛选；失败的数值、布局问题和明确的目标会回传给模型修正。无法评估的关键数据不会被当作通过。

## 飞机使用 SPH

进入 SPH，在面板选择“飞机”或输入明确的飞机需求。自动模式也会识别飞机/喷气/航空类描述；SPH 默认飞机，VAB 默认火箭。界面中的“性能指标”可以填写目标高度、巡航速度、失速速度上限、最低推重比和最低航时。

飞机子集专门保留座舱、吸气式发动机、进气道、纯液体燃料油箱、主翼、操纵面和起落架；不再让便宜火箭发动机和液氧混合油箱占满候选目录。目录仍保留所有已加载部件和自定义螺旋桨模块标识，但缺乏可靠静态模型的自定义发动机不能获得自动性能通过。

0.4.1 进一步区分原生轮组类型 `FREE` / `MOTORIZED` / `LEG`，不把支撑腿和普通驱动轮当成飞机起落架；热防护罩和空气刹车也不会作为主翼提供通过分数。翼面评估遵循原生单/双面升力与节点遮挡标志。明确要求喷气飞机时，不用螺旋桨发动机占据候选位置。

SPH 构型采用原版的水平根部件姿态：机头方向为世界 +Z，右侧 +X，上方 +Y。表面安装角 0/180 为右/左，90 为下方，270 为上方；surfaceHeight 沿机身纵向。

- 主翼/水平控制面可使用 `surfaceOrientation: wing`。
- 垂直稳定面可使用 `surfaceOrientation: fin`。
- `mirrorOf` 从已存在的同型号表面部件生成配对位置与朝向，写入 Mirror 对称引用。配对部件使用相同分级和默认资源。

## 火箭筛选

- 按最高分级先执行的顺序处理发动机激活与解耦边。
- 保留载荷质量，分离后移除不再连接根部件的子树。
- 根据推进剂比例、密度、可达资源池和流动模式计算耗尽事件。
- 逐段计算净轴向推力、发射 TWR、燃烧时间和真空 Δv，默认保留 5% 燃料裕量。
- 检查推力相对质心的偏置、提前部署的降落伞和过早激活的高空/轨道测试发动机。
- 本地轨道目标由实际天体半径、引力参数和目标高度计算理想预算，再加明确的损失余量。其他天体任务需要用户提供 Δv 总预算，不捏造星际转移图。

这是分级资源/理想推进估计，不是轨迹积分；发动机节流策略、精确 KSP 燃料优先级、燃料管和复杂模式需要进一步验证。

## 飞机筛选

- 使用 KSP 的升力/阻力曲线、升力系数、马赫修正和全局乘数；不把 `deflectionLiftCoeff` 冒充真实平方米面积。
- 在实际目标高度的大气密度/压强/音速下计算发动机推力和流量。
- 检查巡航升力、配平迎角、失速速度估计、推力/阻力余量和燃料时长。
- 检查进气资源供需、燃料可达性、左右升力平衡、湿/少油状态的静稳定裕度、操纵面与尾部垂直稳定面。
- 用轮组近似位置检查质心投影是否处于至少三点支撑多边形内。

机身寄生阻力、平均气动弦长、支撑点和静稳定裕度是近似筛选，未代替阻力立方体、起落架展开碰撞、完整配平、地效、FAR 或 CFD。通过筛选仍需游戏中的滑跑和试飞。

## 命令行

```powershell
python -m ksp_autocraft --ksp-root $ksp design '设计一架低成本喷气飞机，左右对称，适合观测合同' --vehicle aircraft --target-altitude 5000 --cruise-speed 150 --max-stall-speed 70 --min-endurance 900 --output plane.json
python -m ksp_autocraft --ksp-root $ksp design '设计两级入轨火箭' --vehicle rocket --target-altitude 80000 --delta-v 4000 --min-twr 1.2 --output rocket.json
```

`--delta-v` 单位 m/s，`--target-altitude` 单位 m，`--min-endurance` 单位秒，质量仍为吨。既有 `validate`/`build` 是结构工具；自然语言 `design` 和游戏内设计按钮额外要求性能筛选通过。完整报告中的 `performance` 保存冻结的目标、指标、问题和方法。
